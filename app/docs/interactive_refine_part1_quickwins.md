## 2. 优化一：TCP Offset 自动由 URDF 驱动

### 2.1 现状与痛点
* 当前在界面优化面板中存在 6 个输入框允许手动编辑 `tcp_offset_xyz` 和 `tcp_offset_rpy`。
* 实际工业喷涂项目中，喷枪末端与法兰的相对安装位姿（TCP）在机械臂 URDF（例如 `cr5_robot_with_gun.urdf` 中的 `spray_nozzle_link`）中已有精确固化。人工二次输入既繁琐又易出错。

### 2.2 设计与实现机制
1. **URDF 智能提取服务**：
   * 后端在初始化或加载机器人模型时，自动解析 URDF 中的末端关节关系（查找 `spray_nozzle_link` 或 `tool0` 相对于 `Link6` 的 fixed joint origin）。
   * 提取平移向量 $(x, y, z)$（单位：mm）与旋转欧拉角 $(rx, ry, rz)$（单位：deg）。
   * 若 URDF 中未定义工具节点（如纯裸机模型 `cr5_robot.urdf`），则 TCP 自动判定为单位阵（Offset 均为 0），无需用户干预。
2. **接口与前端数据流**：
   * 后端通过系统/机器人状态接口（例如 `/api/system/robot/tool_info` 或在模板加载时）下发当前 URDF 的 TCP 偏移量及工具名称。
   * 前端移除手动编辑 TCP 的输入控件，改为只读状态展示标签（如：`TCP: spray_nozzle_link [+2.0, -35.3, +312.2] mm`），当无工具时显示 `TCP: Flange (Default)`。
   * 路径生成与逆解验证流程默认自动应用该 URDF TCP，无需前端通过请求体冗余传输。

## 3. 优化二：模板切换性能加速与图径原子同步

### 3.1 现状与痛点
* 模板切换时，前端依次触发 `fetchFiles`、`fetchSavedMasks`、`fetchManualPaths` 以及 2 组 `verification_report`，发出了 5 个无关联的网络请求。
* 同时 `scan.jpg` 重新加载需要时间，在图片尚未完成渲染前，上一个模板的旧路径或新模板的部分数据已经先行渲染在默认比例画布上，造成视觉错位与撕裂感。
* 网络请求未配备取消机制，若用户快速切换模板，会发生响应乱序与竞态条件（Race Condition）。

### 3.2 优化架构与设计
1. **聚合元数据接口（Batch Overview API）**：
   * 后端提供单次请求接口 `/api/interactive/templates/{name}/summary`，一次性打包返回文件列表、分割掩码元数据、路径数据、缓存报告状态及标定参数。
   * 避免前端通过 5 次 HTTP 请求来回握手，减少网络 RTT 开销。
2. **AbortController 请求中断机制**：
   * 在切换模板时，前端立即中止上一次未完成的所有异步请求，确保仅渲染最新选中的模板数据。
3. **“图片加载屏障”（Image-First Atomic Render）**：
   * 引入双缓冲加载状态：切换模板时，画布进入轻量过渡骨架态。
   * 使用预加载对象监听新模板 `scan.jpg` 的 `onload` 事件，获取准确的 `naturalWidth` 和 `naturalHeight`。
   * 只有在图片位图完全就绪后，才原子化（Atomically）提交图片、分割掩码与路径坐标，确保几何缩放比例与图层严格同步。

## 4. 优化三：2D 路径渲染极简化与起点编号标示

### 4.1 现状与痛点
* 原设计使用 6 种彩虹色区分各条路径，路径重叠或密集时，色彩过多干扰对喷涂工件表面特征（边缘、法向）的观察。
* 无法直观判断哪一条路径先喷涂、哪一条后喷涂，以及每条路径的起始进刀方向。

### 4.2 极简渲染设计
1. **统一线条基调色**：
   * 所有常规路径线条采用统一高对比度、清晰柔和的工业线条色（例如天蓝色 `#38bdf8` 或基于路径状态的专属色，详见下篇）。
   * 降低中间路点圆点的视觉权重，仅保留微小的方向引导箭头与连接线。
2. **起点编号微徽标（Start Badge）**：
   * 在每条路径的第一个路点（Index 0）上方，绘制专属的起点标记徽章（统一采用英文标号如 `P1`, `P2`, `P3...`）。
   * 徽标具备微阴影与高对比度文字底色，即使底图为深色或浅色金属件均清晰可见。
   * 支持 Hover 悬停联动：鼠标悬停在起点编号或路径列表项时，整条路径产生柔和光晕高亮（Glow Accent），便于快速定位。

## 5. 优化四：右侧操作按钮视觉层级与全英文工业风规范

### 5.1 现状与痛点
* 当前右侧操作栏包含 Capture（深灰）、Segment（蓝紫）、Manual TCP（粉红）、TCP Opt（翠绿）、Reconstruct（紫色）等多种色彩，视觉割裂且缺乏高级工业感。

### 5.2 视觉规范与全英文文本定义
1. **基准色规范（对齐 Capture 按钮）**：
   * 所有功能主按钮统一采用深色工业渐变基底（`Slate-800` 至 `Slate-900`），辅以精致的 `1px` 微边框（`border-slate-700/80`）与阴影。
2. **全英文操作按钮与 Tooltip 规范表**：
   * **`Capture`** / **`Wait...`**：
     * Tooltip: `"Capture 2D Color + 3D Depth Data"`
   * **`Segment`** / **`Exit Seg`**：
     * Tooltip: `"MobileSAM Interactive Segmentation"`
   * **`Manual TCP`** / **`Exit Manual`**：
     * Tooltip: `"Manual TCP Path & Normal Design"`
   * **`TCP Opt`** / **`Evaluating...`**：
     * Tooltip: `"Toggle 6-DOF Kinematics & Auto-Fix Panel"`
   * **`Reconstruct`** / **`Rebuilding...`**：
     * Tooltip: `"Surface Poisson 3D Mesh Reconstruction"`
3. **状态交互规范**：
   * **常规状态（Idle）**：统一深灰质感，搭配语义化 Icon（白色/浅灰文字），整洁克制。
   * **激活/运行状态（Active/In-Progress）**：如分割模式开启或手动标定模式开启时，采用柔和的背景微透高亮与主题边框光晕，明确区分当前所处模式。
   * **禁用状态（Disabled）**：统一半透明（40% opacity）与禁止光标，提升操作确定性。

## 6. 分阶段落地执行清单

1. **后端 URDF TCP 解析模块**：
   * 完善 URDF 关节解析逻辑，暴露标准化 TCP 参数读取函数。
2. **后端模板聚合接口开发**：
   * 新增 `/api/interactive/templates/{name}/summary` 接口。
3. **前端状态治理与原子加载**：
   * 引入 `AbortController` 并在 `InteractiveOp.tsx` 中集成图片预加载屏障。
4. **前端 2D 画布渲染重构**：
   * 移除 6 色彩虹分配，上线统一路径样式与起点 `P1/P2` 编号徽章。
5. **右侧操作栏样式重构**：
   * 批量替换右侧 5 个按钮为统一 Slate 工业风设计。
